# 三、第一阶段：立即进行独立实现审查

审查目标不是重新设计整个项目，而是确认现有 B3/B4/B5 能否进入真实实验。

独立审查以下内容：

### A. B4 行为多样性感知机制

检查：

1. Canonical Phenotype 是否能够从真实公开轨迹稳定生成。
2. Levenshtein 距离实现是否正确。
3. 加权行为特征距离是否与冻结权重一致。
4. 行为新颖性计算是否存在候选自身参与计算的问题。
5. 同一 Pareto 层的比较范围是否正确。
6. 相同 Phenotype 的重复控制是否破坏 Pareto 优先级。
7. Crowding Distance 与 Novelty 的归一化是否合理。
8. Genome hash 并列排序是否确定。
9. 缺失轨迹和异常轨迹如何处理。
10. 是否可能通过无意义动作获得虚假的行为新颖性。

重点审查公式：

N(c,F) = min d(c,c')

S(c) = 0.5 CD(c) + 0.5 N(c)

确认公式、代码和实验报告完全一致。

### B. B3 失败反馈机制

检查：

1. 七类失败特征是否存在重复计数。
2. 各类失败率的分母是否正确。
3. 反馈是否只使用已经完成的 Train 评价。
4. 当前候选反馈是否只影响后续 proposal。
5. 是否存在未来信息泄漏。
6. 零反馈是否严格退化为均匀分布。
7. Softmax 是否数值稳定。
8. 探索下限是否始终有效。
9. 随机对照是否使用独立 RNG。
10. 反馈矩阵是否存在人为偏置。

重点检查：

phi_k(F) = sum(W_kj * r_j) / sum(W_kj)

以及最终概率归一化公式。

### C. B5 组合机制

确认：

- B5 同时使用 B3 和 B4。
- B3 不使用 B4 的行为选择。
- B4 不使用 B3 的动态反馈。
- B2 保持标准 NSGA-II。
- 四个实验臂的其他条件一致。

必须保证消融归因成立。

### D. 预算与账本

重点审查：

1. API 请求前成本预留。
2. B1 基线预算独立保留。
3. 各演化臂最终评价预算独立保留。
4. 搜索阶段不能消耗最终评价预算。
5. HTTP 重试计入成本。
6. 预算拒绝不会被记录为真实 API 请求。
7. 实际 Token 结算正确。
8. 预算不足时能够在发送请求前拒绝。
9. 最终评价不可能出现 R2 那种零真实调用的情况。
10. Hash-chain 能够验证事件顺序和数据完整性。

### 审查结论

只允许以下状态：

- ACCEPT_WITH_LIMITATIONS
